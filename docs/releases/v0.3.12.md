# v0.3.12

「页面挂久后提交不上去」修复版：复现并修掉一个结构性缺陷——打印请求在
`Print-Job` 途中被客户端中断（页面挂久后连接失效、浏览器超时中止、关掉标签页）时，
服务端已经受理的打印会丢失「幂等键 → 结果」的落库，幂等键永久停在「进行中」，
之后所有同键重试都被 `409 idempotency_conflict` 拒绝，用户在键的 TTL（默认
10 分钟）内彻底提交不上去，尽管打印其实已经成功。现在提交在独立任务中执行，
同键重试会等待并回放（或接管）结果；另外回收被中断上传留下的临时文件。
后端测试 52 → 61（新增 9 个先红后绿的回归用例），前端无改动。无损升级。

## 🐛 修复

- **客户端断开后幂等键卡在「进行中」，同键重试永远 409**：`POST /api/print`
  以前直接在请求 future 里做提交——客户端一断开，hyper 就丢弃该 future，
  已经发出的 `Print-Job` 照常打印，但 `Idempotency-Key` 的条目再也没人推进到
  终态。前端在重试时会刻意复用同一把键（这正是幂等键的意义），于是每一次
  「提交 / 重试提交」都撞上 `409`，观感就是「一直转圈、没反应、任务提交不上去」。
  现在：
  - 提交（含失败对账与幂等键落库）在 `tokio::spawn` 出的独立任务里执行，
    生命周期与连接无关——客户端断开只会丢弃等待，不再取消已经受理的打印；
  - 同键**同负载**的重复请求不再立刻 409，而是在
    `JUST_PRINT_IDEMPOTENCY_WAIT_SECS`（默认 15 秒）内等待在途请求结束：
    成功则回放其结果（带 `Idempotency-Replayed: true`，不会重复出纸），
    失败/被放弃则由本次请求接管重试，等待超时才回 `409` + `Retry-After: 1`；
  - 任务被 panic 或运行时中止打断时，兜底守卫会按本次尝试的 token 释放条目，
    既不会留下「进行中」，也不会误删已经接管的新尝试（防止重复出纸）。
- **被中断的上传会长期占用磁盘**：上传在写入/转换途中被客户端断开或请求超时时，
  源文件（最大 64 MiB）与 LibreOffice 配置目录都没有登记进 `FileStore`，
  普通 TTL 清理看不到它们，容器会一直占着这些残留。现在上传处理器持有
  RAII 守卫，请求提前结束（含 future 被丢弃）就地删除半成品；后台清理任务再按
  mtime 兜底回收未登记的残留文件与目录（mtime 在 TTL 之内的一律保留，
  不会误删正在处理的产物）。

## 🧪 测试与验证

- 新增 9 个「先红后绿」回归用例（后端 52 → 61），其中三个用真实 hyper 监听 +
  原始 TCP 客户端复现网络中断：
  - `client_disconnect_does_not_strand_idempotency_key`：`Print-Job` 进行中断开
    连接，随后同键重试必须回放同一个 CUPS 任务，且 `Print-Job` 只发出一次
    （既不重复出纸，也不再永久冲突）。
  - `concurrent_same_key_request_replays_instead_of_conflict`：同键并发只提交一次，
    后到的请求等待并回放首次结果。
  - `waiting_retry_takes_over_when_first_submission_fails`：首次提交被 CUPS 拒绝
    （HTTP 503）时，等待中的同键重试接管并成功——即用户点「重试提交」的路径。
  - `interrupted_upload_leaves_no_temp_files`：上传途中断开后临时目录不残留
    未登记的半成品。
  - 存储层：在途等待者回放结果 / 接管重试 / 等待预算到期回冲突、
    迟到的放弃不得删掉已接管的尝试、残留清理只删过期且未登记的条目。
- `cargo fmt --check`、`cargo clippy --all-targets --all-features -D warnings`、
  `cargo test --all-features`（61 个）全部通过；前端未改动，仍整套跑通
  `tsc -b` / ESLint / Vitest（55 个）/ `vite build`；入口脚本 16 项断言通过。
- 冒烟（真实二进制 + `curl`，无 CUPS）：`/healthz` 200、`/readyz` 503、
  未带令牌 401、`/api/formats` 正常、PDF 上传 201、打印返回 `503` +
  `Retry-After: 1`，`/tmp/just-print` 只留下已登记的文件、无残留。

## 升级说明

直接替换镜像即可，客户端无需改动：接口路径、请求/响应结构与错误码均未变，
只有「同键重试」的语义更友好（等待并回放，而不是立刻 409）。新增可选环境变量
`JUST_PRINT_IDEMPOTENCY_WAIT_SECS`（默认 15 秒，设为 0 不允许）。
