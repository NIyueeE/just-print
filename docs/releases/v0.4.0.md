# v0.4.0

常规维护版：修掉一条已经烂掉的门禁配方、清掉前端 7 条 high 依赖公告、把 10 个
Rust 依赖更新到最新兼容版本，并修正三处文档与代码不一致。`Cargo.toml` 与
`frontend/package.json` 的版本号此前一直停在 0.3.0，本版同步到 0.4.0。

## 🛠 修复

- **`just audit` 完全不可用**：cargo-audit 0.22 起把 advisory / license 检查
  合并进默认子命令，旧写法 `cargo audit --deny warnings advisories licenses`
  直接报 `unrecognized subcommand 'advisories'` 并以退出码 2 失败。也就是说
  文档里的「依赖审计」这道门禁**从来没有真正跑起来过**。改为 `cargo audit
  --deny warnings`，行为不变（0 漏洞 + 无警告才通过）。
- **前端 7 条 high 依赖公告**：`vite` 8.2.0 引入的 `source-map-js`（事件循环
  DoS）与 `launch-editor`（Windows 符号链接检查绕过），`jsdom` 引入的
  `undici` 8.10.2 的 4 条公告（DoS、缓存污染与跨用户泄露、TLS 校验绕过、
  TLS 1.2 重协商 DoS）。这些都是**开发期依赖**（构建、测试、开发服务器），
  不进生产产物，但会持续让 `just audit` 报红。已更新 `vite` 8.3.5、
  `jsdom` 30.1.3 及其传递依赖，`bun audit --audit-level=high` 现在 0 漏洞。
- **文档与代码不一致（三处）**：
  - `docs/mcp.md` 写「设备端点上限 32，超出返回 404」，实际返回 `400`
    （`AppError::BadRequest`）；
  - `src/conversion.rs`、`docs/api.md`、`docs/architecture.md` 仍写
    「LibreOffice 7.4.7」，而镜像基于 Debian trixie，实际为 25.2；
  - `docs/architecture.md` 的 LO 首段吞段说明钉在具体版本号上，改为描述缺陷
    本身（规避逻辑与版本无关）。

## 升级说明

直接替换镜像即可，无损升级：接口路径、请求/响应结构与错误码均未变。

- 依赖更新含 `rmcp` 3.6 → 3.8（MCP 协议库的小版本跨越，用到的 API 未变，
  已用容器冒烟里的 8 个 MCP 步骤验证）；`aws-lc-rs` 升级会重新编译该加密
  后端，构建时间略增。
- 之前 `just audit` 一直是失败状态（`unrecognized subcommand`），现在这条
  门禁恢复可用；CI 的 `Dependency audit` 作业走 `rustsec/audit-check`，不受
  本次修改影响，行为与之前一致。
- 三处文档修正不影响运行时行为。
