# v0.3.7

运行基座从 **Debian 12 (bookworm)** 升到 **Debian 13 (trixie)**。这一版**不含**任何
功能性改动——按「先升级基座，看上游新版本是否顺带解决问题」的结论，本次刻意不加
任何兜底/后处理实现。

## 🔄 基座升级

| 组件 | 旧（bookworm） | 新（trixie） |
| --- | --- | --- |
| CUPS | 2.4.2 | **2.4.10** |
| cups-filters | 1.28.17-3 | 1.28.17-6 |
| Ghostscript | 10.0.0 | **10.05.1** |
| LibreOffice | 7.4 | **25.2** |
| HPLIP（hpcups 驱动） | 3.22.10 | 3.22.10 |
| `cups-pdf` 包名 | `cups-pdf` | `printer-driver-cups-pdf`（Debian 改名） |

## ❌ 本次未包含（有意）

- **PCL-XL 页序修正（原计划的 B）**：`pxaDuplexPageSide` 逐页正反面改写不做。
  该问题根因在 Ghostscript 的 PCL-XL 设备（`pclxl_put_params()` 的 `Duplex` 分支
  缺新旧比较 → 页计数被向上取偶 → 第 2 页起被标成「正面」），trixie 的 10.05.1
  里这段设备代码与 10.0.0 **完全一致**，因此本版只能验证「新版 PDF 解释器的行为
  是否不再触发它」，不能保证修好。
- 任何包装过滤器、自带 `usb` 后端等侵入式实现。

## ⚠️ 升级注意

- **USB 打印已验证可用**：CI 冒烟测试里打印出的实际后端清单为
  `beh cups-brf cups-pdf dnssd driverless driverless-fax http https ipp ipps lpd mdns parallel serial snmp socket usb`
  ——`usb` 在（与 bookworm 镜像一致），USB 队列照常创建。
  （背景：`usb`/`socket`/`lpd`/`snmp`/`dnssnd`/`mdns` 这几个后端既不在
  `cups-daemon` 的文件清单里、也不属于任何 dpkg 包，但镜像里确实存在——Debian 打包
  的一个怪点；CI 里保留这条可见性检查作为回归保护。）
- LibreOffice 从 7.4 跳到 25.2，文档转换的渲染细节可能有变化；如遇到个别文档
  转换失败请反馈样张。

## ✅ 验证

- `just check` 全绿（后端 33 个测试、前端 44 个测试、入口脚本 24 项断言）。
- CI：镜像构建 + 端到端冒烟（401 / 就绪 / 上传→预览→打印→完成 / 幂等重放 /
  任务列表 / 取消 / 删除文件），并打印 CUPS 后端清单与 usb 后端存在性。

## 升级后请验证

1. 队列还在、能打印（USB 队列名不变）：`podman exec just-print sh -c 'lpstat -p -d'`
2. 双面是否已随上游修好（跑一次正常打印即可；若仍是单面，下一步再决定是否做
   PCL-XL 页序修正或改走 PCL5 通道）。
3. 分辨率仍按界面选择生效（v0.3.6 的 PPD 风格 `Resolution=` 兼容属性仍在）：
   `podman exec just-print sh -c "grep 'Ghostscript command line' /var/log/cups/error_log | tail -1"`
