# v0.3.8

清理历次"补丁叠补丁"留下的残留与可观测性问题。**没有功能性行为变化**，唯一
用户可见的差异是：USB 队列创建失败时不再只丢一行无信息量的 warning。

## 🧹 清理

- **移除跨厂商"猜型号"的模糊匹配**：删掉 `entrypoint.sh` 里的 `match_ppd()` 与
  `is_hp_vendor()`（-41 行）。这段逻辑是 v0.3.1 引入的，也是「联想被猜成 HP」那次
  误配的来源；v0.3.3 起驱动选择已改为「device-id 取候选 + 逐行校验厂商/型号」，
  v0.3.5 又补了候选校验，模糊匹配实际只在"device-id 查不到厂商 PPD"这一窄缝里生效。
  现在驱动选择只有两条路：
  1. 可信候选（device-id 候选里能对上厂商与型号的 PPD）；
  2. 回落到通用 PCL PPD，并提示用 `JUST_PRINT_USB_PPD` 显式指定厂商驱动。
  按「跨厂商猜错会直接打出乱码，宁可退回通用驱动」的原则，不再做任何猜测。
- **`lpadmin` 失败不再静默**：创建队列的 4 次尝试（带选项 → 不带选项 → 通用 PPD）
  原先全部用 `>/dev/null 2>&1` 吞掉错误，全部失败时只打一行
  `failed to auto-add USB printer`。现在保留每次尝试的 CUPS 报错，最后一次的报错会
  随 warning 一起打印（例如 `JUST_PRINT_USB_OPTIONS` 写错时能直接看到原因）。
- **前端删掉 PPD 时代的死常量**：`DuplexNoTumble` / `DuplexTumble` / `None` 的取值
  标签、`DUPLEX_LONG_EDGE` 里的 PPD 拼写（`duplexnotumble`、`longedge` 等）以及
  相关注释——v0.2.x 的 `lpoptions` 目录早已换成标准 IPP 属性名，这些映射永远不会
  命中；同步更新了 `options.test.ts` 的断言。
- 文档同步：`docs/deployment.md` 的驱动选择说明、`AGENTS.md` 的镜像描述不再宣称
  "HP 模糊兜底"。

## ✅ 验证

- `just check` 全绿：后端 33 个测试、前端 44 个测试、入口脚本 **16** 项断言
  （原先 24 项，删掉的 8 项都是 `is_hp_vendor`/`match_ppd` 的专属用例；
  URI 解析、device-id 拼装、候选 PPD 校验、选项解析的断言全部保留）。
- 无需重新构建镜像逻辑以外的东西：本次只改入口脚本、前端常量与文档。
