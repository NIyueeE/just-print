# v0.3.11

上传卡死修复版：修掉「上传纯 PDF 一直卡住」的两个结构性问题——后端让 PDF 直通
排队等 LibreOffice 转换槽、前端上传请求没有客户端超时。后端测试 50 → 52，前端
54 → 55，均含「先红后绿」的回归测试。无损升级。

## 🐛 修复

- **PDF 直通排队等 LibreOffice 转换槽（上传卡死放大器）**：上传处理器此前对所有
  格式都先获取转换信号量（默认 2 槽），但 PDF 直通只读 `%PDF-` 魔数、根本不启动
  soffice，却也要排在槽里。只要前面有尚未结束的 LibreOffice 转换占满槽位，一个
  PDF 上传最多干等一整个转换周期（默认 2 分钟），用户观感就是「上传卡住」。现在
  以 `conversion::is_passthrough_extension` 为单一来源，只有真正要启动 soffice 的
  格式才排队；新增全链路测试占满唯一转换槽后断言 PDF 上传仍能快速完成。
- **上传请求没有客户端超时（永远转圈）**：`uploadFile` 走 XMLHttpRequest，默认
  `timeout = 0` 永不超时，是唯一没有超时的请求；服务端或中间链路不返回响应时，
  进度区会永久转圈而不是给出错误。现在按后端 `request_timeout`（5 分钟）设置
  `xhr.timeout`，超时转成 `timeout` 错误并提示「上传超时，请重试」；同时补充
  `gateway_timeout`（504）的专属文案「服务端处理超时（可能仍在转换），请稍后重试
  或换更小的文件」。
