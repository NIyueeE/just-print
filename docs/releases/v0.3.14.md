# v0.3.14

内置 MCP 端点：Claude Code / Cursor 这类终端 agent 可以直接查设备、上传 PDF、提交
打印、跟踪任务。文件字节不经过模型上下文——agent 执行一条 curl 把文件从磁盘推到
服务器，模型只负责签发一张一次性票据。同一版里还做了依赖全量更新、两条 rustls
安全公告修复、工具链声明，并把 MCP 链路纳入容器冒烟。

## 🔌 MCP 接入

**为什么上传要绕一步。** 浏览器能上传是因为它跑在你机器上：读文件、发 POST。MCP
没有浏览器——工具参数是模型生成的文本，1 MB 的 PDF 变成 base64 是约 34 万 token，
而且逐字复述会损坏内容。所以这版把控制面和数据面拆开：工具走 MCP，字节走终端。

**端点。** `POST /mcp`，与 `/api` 共用同一个 Bearer 令牌，外加必填的
`X-Just-Print-Device` 请求头（CUPS 队列名）；缺头直接 400，一个连接只对应一台
设备。同时支持 `2026-07-28`（无状态、逐请求 `_meta`）与 `2025-11-25`
（`initialize` 握手）两个协议版本。

**七个原子工具。** `get_device` 给出设备状态与 IPP 选项目录；`create_upload_ticket`
签发票据；`print_document` 提交任务；`list_jobs` / `get_job` / `cancel_job`
管任务；`delete_file` 清理误传。每个工具只做一件事，失败边界清楚：上传成功
不代表打印成功。任务工具还会校验 `job_id` 的 `<device>-<n>` 前缀，操作不到别的队列。

**一次性票据。** `create_upload_ticket` 返回一个 5 分钟有效、只能兑换一次的
`POST /uploads/{ticket}` 地址，以及一条可直接执行的 curl（把 `{path}` 换成本机
文件）。票据不绑定令牌，泄露上限只是「多出一个 PDF」；重放返回
`401 invalid_ticket`。该通道只收 PDF（校验 `%PDF-` 魔数），转换由 agent 负责。

**幂等。** `print_document` 由 `file_id` + 设备 + 选项派生 `Idempotency-Key`，
重试回放首次结果、不重复出纸；要打多份用 `options.copies`。

工具内部走已装配的 `/api` 路由，参数校验、幂等、错误信封与网页端是同一份代码。
详细用法见新增的 `docs/mcp.md`。

## 🔐 依赖与安全

- 修复两条 emSign 相关公告：`rustls-webpki` 0.103.15 → 0.103.16
  （RUSTSEC-2026-0382）、`webpki-root-certs` 1.0.9 → 1.0.10
  （RUSTSEC-2026-0383）。二者经 `ipp → reqwest → rustls-platform-verifier`
  进入，应用层无法绕过。
- 依赖全量更新：`tower-http` 0.6 → 0.7（树里唯一的破坏性跳跃，用到的中间件 API
  未变，无需改代码），`tokio` 1.54、`uuid` 1.28、`serde_json` 1.0.154、
  `thiserror` 2.0.21，外加约六十个传递依赖。`cargo update --dry-run` 已无可更新项。
- `cargo audit`：0 漏洞、0 警告（顺带清掉了此前 `yoke-derive` 的 yanked 警告）。

## 🛠 构建与工具链

- 新增 `rust-toolchain.toml`（`stable` + clippy/rustfmt），本地与 CI 的工具链
  不再依赖机器默认值。

## 升级说明

直接替换镜像即可，Web 端与现有 API 的路径、请求/响应结构均未变。变化都在新增面：

- MCP 是**可选**的：不配置客户端就不会有任何调用，端点和 `/api` 共用同一个令牌，
  不新增令牌种类。
- 新增错误码 `invalid_ticket`（401），只出现在票据上传通道。
- 新增端点 `POST /mcp` 与 `POST /uploads/{ticket}`，契约见 `docs/api.md`。
- 若你把 `JUST_PRINT_CUPS_URI` 配成 `https://`（ipps），本版修复的两条公告与这条
  链路相关；默认的明文 IPP 部署不受影响。
