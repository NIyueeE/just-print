# v0.3.0

这是一次大版本更新：**CUPS 集成从 `lp` / `lpstat` / `lpoptions` / `ipptool` 子进程改为标准 IPP over HTTP**，打印提交具备真正的幂等语义，前端按设计系统 / 无障碍标准整体重构。API 契约有破坏性变更，升级前请阅读「破坏性变更」。

## ⚠️ 破坏性变更

- **打印幂等**：`POST /api/print` 支持标准 `Idempotency-Key` 请求头。同一键 + 相同负载在保留期（默认 10 分钟）内只产生一个 CUPS 任务，重复请求回放首次响应并带 `Idempotency-Replayed: true`；键被复用于不同负载返回 `409 idempotency_conflict`。强烈建议所有客户端都发送该头。
- **打印机选项结构**：`GET /api/printers` 的 `options` 由 PPD / `lpoptions` 名称改为标准 IPP job 属性名（`media`、`sides`、`print-color-mode`、`print-quality`、`printer-resolution`、`copies`、`number-up` 等），并以 `kind` 判别联合表示取值类型（`keyword` / `enum` / `integer` / `integer_choices` / `resolution`）。
- **任务 id**：`job_id` 统一为 `<printer>-<job>` 形式；`GET /api/jobs/{id}` 只接受该形式，或仅在登记表中唯一匹配的纯数字任务号，否则返回 `400`（避免多打印机任务号重复导致状态串台）。
- **新增端点**：`GET /api/formats`、`GET /api/jobs`、`DELETE /api/jobs/{id}`、`DELETE /api/files/{id}`、`GET /readyz`、`GET /api/metrics`。
- **错误语义**：CUPS 不可达 → `503 service_unavailable`（附 `Retry-After`）、超时 → `504 gateway_timeout`、协议异常 → `502 bad_gateway`；新增 `409 conflict` / `409 idempotency_conflict`。所有响应带安全头，`/api` 响应 `Cache-Control: no-store`，并带 `x-request-id`。
- **无打印机不再是错误**：CUPS 中没有打印机时 `GET /api/printers` 返回 `200 {"printers":[]}`，不再返回 500。

## ✨ 新功能

### 后端

- **标准 IPP over HTTP**：使用 RFC 8011 操作 `CUPS-Get-Printers` / `Get-Printer-Attributes` / `Print-Job` / `Get-Job-Attributes` / `Get-Jobs` / `Cancel-Job` 直接与 CUPS 通信，去掉每个请求 fork 子进程的开销；打印机快照与任务状态带短 TTL 缓存 + singleflight，前端轮询不会放大为 CUPS 请求风暴。
- **幂等与失败对账**：幂等键记账 + 指纹校验；提交时把短标记写入 IPP `job-name`，若 `Print-Job` 响应丢失（超时 / 连接失败），服务端按标记 `Get-Jobs` 找回已创建任务后再决定是否允许重试，避免重复出纸。
- **任务管理**：应用层任务登记表 + `GET /api/jobs`（每台打印机一次查询，按需过滤 `active`）、`GET /api/jobs/{id}`、`DELETE /api/jobs/{id}` 取消。
- **流式上传**：上传改用分块落盘（不再整文件驻留内存），并发上传由信号量限制；PDF 魔数只读前 5 字节。
- **可观测性**：每请求 `x-request-id` 与追踪 span、打印审计日志、`GET /api/metrics` Prometheus 指标（请求计数/耗时直方图、IPP 操作、上传/转换/打印结果、文件与任务计量）、`GET /healthz` 存活与 `GET /readyz` 就绪探针（真实查询 CUPS）。
- **安全**：CSP、`X-Content-Type-Options`、`Referrer-Policy`、`X-Frame-Options`、`Permissions-Policy` 默认开启；文件 id 改为 CSPRNG（UUID v4）；Bearer scheme 大小写不敏感。
- **可调参数**：上传上限、上传/转换并发、转换超时、临时文件 TTL、清理周期、IPP 超时、打印机/任务缓存、幂等键 TTL、请求超时全部可通过环境变量配置。

### 前端

- **设计系统**：完整设计令牌（色彩、间距、字号、圆角、阴影、控件高度、层级、动效）与 Gruvbox 暗 / 亮主题（系统偏好 + 手动切换并持久化）；样式按组件拆分，组件样式不再出现硬编码颜色；muted 文本对比度按 WCAG AA 校正。
- **无障碍**：文件选择可键盘操作（视觉隐藏但保留 Tab 焦点），拖拽区支持 Space/Enter；错误使用 `role="alert"` 且不自动消失，成功/信息使用 `role="status"`；令牌进入前服务端校验并给出错误提示；打印前弹出带焦点陷阱的确认对话框（汇总文件、打印机、份数、单双面、纸张、分辨率）。
- **交互**：上传显示百分比并支持取消；打印失败在 503/504/网络抖动与幂等冲突时复用同一幂等键指数退避重试；任务支持取消、重打、清除与计数；任务被 CUPS 清理时只标记「已清理」，不再误清空已上传文件。
- **轮询与状态**：任务轮询带重入保护、`AbortController`、指数退避（遵守 `Retry-After`）、页面隐藏暂停；单一 reducer + context 取代原先分散在多个组件的重复状态。
- **工具链**：ESLint（含 `jsx-a11y`）、Prettier、Vitest + Testing Library；`just frontend` 现在执行类型检查 → lint → 测试 → 构建。

## 🐛 修复

- 修复「无打印机」被当作服务端 500、前端空态永不显示的问题。
- 修复多打印机下裸任务号歧义导致的任务状态串台。
- 修复任务被 CUPS 清理（404）时前端误报「服务已重启」并清空已上传文件的问题。
- 修复上传整文件驻留内存、转换排队无上限导致的资源风险。
- 修复前端状态样式类名错配（`completed` / `canceled` 状态无样式）。
- 修复子进程超时后 `lp` 已被 CUPS 接受却返回 500、客户端重试造成重复出纸的路径。
- 修复 `ipptool` 请求文件遗留在 `/tmp` 根目录、游离于清理体系之外的问题。
