# v0.3.5

修复 USB 驱动选择的最后一处误配：`lpinfo -m --device-id` 的返回结果在部分 CUPS
版本上并没有真正按 device-id 过滤，直接取第一行会选中**无关厂商的 PPD**。

## 🐛 修复

- **候选 PPD 必须通过厂商/型号校验**：以联想 LJ4000D 为例，实测
  `lpinfo -m --device-id 'MFG:Lenovo;MDL:LJ4000D;'` 的返回里第一行是 HPLIP 的
  `drv:///hpcups.drv/apollo-2100.ppd`（"Apollo 2100"），该 PPD 与联想无关且没有
  Duplex / Resolution 选项，导致队列既不能双面也没有分辨率可调。
  现在会逐行校验：厂商需在 MakeModel 中作为独立词出现（避免 "hpcups" 里的 "hp"
  干扰），且型号里的首段数字也要出现（4000 ≠ 2100）；都不满足则回落到通用 PPD
  并打印提示，绝不使用无关驱动。
- 该问题只影响「未显式指定 `JUST_PRINT_USB_PPD`」的 USB 队列；显式指定时用户配置
  优先。

## 🧪 测试

## 使用提示

- 若日志出现 `note: 未找到 <厂商> <型号> 的专用驱动`，说明镜像里没有该机型的 PPD，
  请用 `JUST_PRINT_USB_PPD` 指定（例如 `lsb/usr/cupsfilters/pxlmono.ppd`）。
- 排查驱动是否真的生效：
  `podman exec -it just-print env | grep JUST_PRINT_USB`，
  以及 `podman logs just-print | grep 'auto-added'` 查看实际选中的 PPD。
