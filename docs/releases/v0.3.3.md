# v0.3.3

修复 v0.3.1 引入的**串厂商驱动误配**：驱动选择改为 CUPS 标准的 IEEE 1284
device-id 匹配，不再用型号字符串猜厂商。

## 🐛 修复

- **联想 LJ4000D 被误配成 HP LaserJet 4000**：v0.3.1 的模糊匹配会把型号里的
  `lj` 还原成 `laserjet` 再去比对厂商 PPD，导致 `usb://Lenovo/LJ4000D` 命中了
  `HP LaserJet 4000 Series` 的 PPD。现在改为：
  1. 从 USB URI 取厂商与型号，拼成 `MFG:…;MDL:…;` 交给
     `lpinfo -m --device-id`，由 CUPS 按 PPD 的 `1284DeviceID` 匹配——
     **厂商与型号都要匹配**，跨厂商不会再误配；
  2. 仅当厂商是 HP 且 device-id 无结果时，才使用原来的保守模糊匹配；
  3. 仍无结果则回落通用 PCL，并在日志中打印 device-id 与
     `JUST_PRINT_USB_PPD` 提示。
- **`JUST_PRINT_USB_OPTIONS` 写错不再丢打印机**（v0.3.2 已修）：选项被
  `lpadmin` 拒绝时退回不带选项重建队列。

## 📚 文档

- [部署指南](../deployment.md) 新增「驱动是怎么选的（以及为什么无法全自动）」：
  说明 CUPS 的两条正路（IPP Everywhere 全自动 / 传统 PPD 按 1284 device-id），
  并给出联想 LJ4000D（PCL6 + BR-Script3、标配双面）的推荐配置：

  ```ini
  Environment=JUST_PRINT_USB_PPD=lsb/usr/cupsfilters/pxlmono.ppd
  Environment=JUST_PRINT_USB_OPTIONS=OptionDuplex=True
  ```

## 升级提示

- 用错了 PPD 的队列需要重建：容器重建（`/etc/cups` 未持久化）即会按新逻辑重新
  匹配；若你持久化了 `/etc/cups`，先 `lpadmin -x <队列>` 再重启。
- 升级后如果日志出现 `note: 未找到 <厂商> <型号> 的专用驱动`，说明该机型的 PPD
  不在镜像里，请按日志提示用 `JUST_PRINT_USB_PPD` 指定厂商 PPD，或使用通用
  PCL6 / PostScript 驱动。
